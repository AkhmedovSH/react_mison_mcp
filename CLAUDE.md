# CLAUDE.md — mison_mcp

MCP-сервер Mison (удалённый, `mcp.mison.uz`; пакета в npm нет): тонкая обёртка над партнёрским API `/api/integrations/v1/*`. Отдельной логики
не содержит — каждый инструмент вызывает метод API. Устройство и подключение — в `README.md`.

## Главное правило: API и MCP меняются вместе

Бэкенд API лежит в `D:\Mison\laravel_mison.uzb` (`app/Http/Controllers/External/Integration*`, маршруты
`routes/api/integrations.php`), доки — в `D:\Mison\mison_api` (`docs/*.md`, `openapi.yaml`). **Когда в API
добавили или изменили метод, поле, параметр, статус или ошибку — обнови этот пакет в той же задаче.** Без этого
ИИ-ассистенты клиентов не увидят новую возможность или будут вызывать старую.

Чек-лист при изменении API:

1. **Инструмент** в `src/tools/<группа>.js`:
   - чтение — `getTool({ name, group, title, description, path, input })`; запрос чтения по протоколу POST
     (расчёт, OLAP) — `postReadTool`;
   - запись — `writeTool({ ..., summary, validate, run, idempotent, destructive })`. Он сам добавляет параметр
     `confirmed`: без `confirmed=true` инструмент ничего не отправляет, а возвращает итог для показа человеку.
     Не обходи это ни для какой записи.
2. **Группа.** Новая область — в `GROUPS` (`src/tools/define.js`) и в `ALL_TOOLS` (`src/tools/index.js`); общий
   инструмент может принадлежать нескольким группам (`group: ['receipts', 'inventories']`).
3. **Описание — для модели**: на какой вопрос отвечает, какие ограничения (период, потолок), что опасно, откуда
   брать id. Параметры — через `zod`, с `.describe()`. Новое поле существующего метода — добавь в `input`.
4. **Идемпотентность записи.** Если у метода есть `external_id` / `event_id`, инструмент генерирует его сам
   (`newExternalId()`) до запроса и возвращает человеку в итоге подтверждения: повтор при обрыве сети безопасен.
5. **Тесты.** Ответ нового метода — в `test/mock-api.js`, сценарий — в `test/e2e.test.js` (список инструментов,
   передача параметров, запись без и с `confirmed`, ошибки). Прогон: `npm test` — все тесты должны проходить.
6. **README** (таблица групп, число инструментов, безопасность записи), **версия** в `package.json`
   (новая возможность — минорная), `INSTRUCTIONS` в `src/index.js`, если появился сценарий, о котором модели надо знать.
7. **Доки** `mison_api/docs/mcp.md` — таблица групп; страницу самого метода пишет задача про API.

## Запись: правила безопасности

- Все инструменты записи требуют подтверждения человеком (`confirmed=true` только после явного «да»).
- Проведение, которое двигает деньги или остаток, по умолчанию мягкое там, где у API есть режим черновика
  (инвентаризация — `is_draft: true`); жёсткие режимы включаются явным параметром.
- Идентификаторы (`point_id`, `warehouse_id`, `supplier_id`, `product_id`) модель берёт из справочных
  инструментов, не придумывает — это сказано в описании каждого инструмента записи.
- `MISON_MCP_READONLY=true` не регистрирует запись вообще; `MISON_MCP_GROUPS` отбирает группы, `core` всегда.

## Стек и стиль

- Node 18+, ESM (`"type": "module"`), `@modelcontextprotocol/sdk` 1.x, `zod` 4. Без TypeScript и сборки.
- Отступы — табы, без точек с запятой, одинарные кавычки; комментарии и тексты для модели — по-русски.
- Имена инструментов — `mison_<что>`; ответы API отдаём как есть (JSON), не пересказываем; большие ответы
  режет `src/result.js`.
- stdout занят протоколом — логируем только в stderr.

## Два режима запуска

- **stdio** (`src/index.js`) — для разработки и тестов, ключ из `MISON_API_KEY`; клиентам не раздаём.
- **HTTP** (`src/http.js`) — удалённый сервер `mcp.mison.uz`: Streamable HTTP без сессий, ключ клиента в
  `Authorization: Bearer`, общий кэш токенов (`TokenCache` в `src/client.js`), лимиты на ключ и на неудачные входы,
  сужение набора заголовками `X-Mison-Readonly` / `X-Mison-Groups`. Тесты — `test/http.test.js`.

Оба режима собирают сервер одной функцией `createMisonServer` (`src/server.js`): новый инструмент добавляется один раз и
появляется в обоих. Файлы развёртывания (systemd, nginx, выкладка с откатом) — `deploy/`, порядок — `deploy/README.md`.
На проде стоит Node 24 (`/opt/node`, ссылки в `/usr/local/bin`); зависимости собирает `release.sh` и кладёт в архив готовыми,
а не качает сервер. Выкладка — `deploy/release.sh` с машины
разработчика; новая версия инструментов не доезжает до клиентов удалённого режима, пока её не выложили.

## Запуск
