# Mison MCP

MCP-сервер Mison: подключает ИИ-ассистента (Claude, ChatGPT, Cursor и другие приложения с
поддержкой MCP) к данным заведения. Ассистент сам вызывает нужные отчёты и действия:
«сколько продали за неделю», «посчитай KPI кассиров», «что у нас с остатками», «оформи приход»,
«поставь бронь на пятницу».

Под капотом — [партнёрское API Mison](https://api.mison.uz): сервер получает токен по вашему
API-ключу и вызывает те же методы. Ничего нового в данные он не добавляет: что API не отдаёт
ключу, того не увидит и ассистент.

## Что такое MCP

MCP (Model Context Protocol) — открытый стандарт, по которому ИИ-приложение подключает
внешние «инструменты». Вместо того чтобы писать своего бота и учить его нашему API, клиент
вставляет ключ в настройки Claude или ChatGPT — и ассистент видит список наших инструментов
с описаниями, сам выбирает нужный, подставляет параметры и читает ответ. MCP-сервер — маленькая
программа, которая стоит между ассистентом и API. Наш работает у нас по адресу `https://mcp.mison.uz/mcp`:
клиент подключает его своим API-ключом, устанавливать ничего не нужно.

## Что умеет

58 инструментов в девяти группах. `core` включена всегда.

| Группа | Что внутри | Запись |
|---|---|---|
| `core` | точки, справочники (типы оплат, заказов, причины отмены) | нет |
| `reports` | OLAP продаж, зарплата, **KPI**, P&L, смены, чеки, движение денег, удаления, сотрудники, посещаемость, долги организаций и поставщиков, ABC-XYZ, товары, стоп-лист, остатки, приходы, инвентаризации, движение товаров, подписка | нет |
| `receipts` | склады, поставщики, товары, **приходная накладная** (проводится сразу или черновик `is_draft`) | да |
| `inventories` | остатки склада, **расчёт инвентаризации без записи**, **создание** (по умолчанию черновик), чтение | да |
| `transfers` | получатели, остатки, **перемещение между складами** (проводится сразу) и **на другой логин** (по умолчанию черновик) | да |
| `menu` | витрины, меню точки, номенклатура | нет |
| `orders` | расчёт корзины, **создание**, статус, **отмена** заказа | да |
| `reservations` | правила, залы, свободное время, брони: **создать, перенести, отменить** | да |
| `attendance` | сотрудники, смены, **отметки прихода и ухода** | да |

Какие инструменты реально сработают, решает ключ: отчёты — галочка «Доступ к отчётам»,
приход — «Приход товара», инвентаризация — «Инвентаризация», перемещения — «Перемещение товара», брони — «Бронирование столов» и т. д. Без галочки инструмент ответит
понятной ошибкой 403.

## Подключение

Нужен API-ключ: кабинет → **Интеграции → API-ключи**. Для ассистента лучше завести **отдельный ключ** с минимумом
прав: его можно будет отключить, не трогая заказы и отчёты.

Claude Code:

```bash
claude mcp add --transport http mison https://mcp.mison.uz/mcp --header "Authorization: Bearer ВАШ_КЛЮЧ"
```

Cursor, `~/.cursor/mcp.json`:

```json
{ "mcpServers": { "mison": { "url": "https://mcp.mison.uz/mcp", "headers": { "Authorization": "Bearer ВАШ_КЛЮЧ" } } } }
```

Пакета в npm нет: подключение только к удалённому серверу. Веб-интерфейсы claude.ai и ChatGPT пока не подходят —
им нужен OAuth. Локальный запуск (`node src/index.js`, stdio, ключ из `MISON_API_KEY`) оставлен для разработки и тестов.

## Удалённый режим (HTTP)

Сервер (`node src/http.js`) слушает
`POST /mcp`, ключ клиента — в заголовке `Authorization: Bearer <ключ>`. Сервер работает без сессий, на каждый запрос
собирает инструменты под ключ клиента, токены Mison кэширует в памяти по sha256-отпечатку ключа, а сам ключ не хранит и
не пишет в журнал. Клиент может сузить набор заголовками `X-Mison-Readonly: true` и `X-Mison-Groups: reports,receipts`;
расширить сверх настроек сервера нельзя. Лимиты: 300 запросов в минуту на ключ, 30 неудачных входов в минуту с адреса.

Развёртывание на сервере (systemd, nginx, выкладка с откатом) — в [`deploy/README.md`](deploy/README.md).

Переменные HTTP-режима (в дополнение к общим ниже): `PORT` (3300), `HOST` (127.0.0.1), `MISON_MCP_TRUST_PROXY`,
`MISON_MCP_HTTP_RATE_LIMIT`, `MISON_MCP_HTTP_AUTH_FAIL_LIMIT`, `MISON_MCP_ALLOWED_ORIGINS`, `MISON_MCP_MAX_BODY`, `MISON_MCP_LOG`.
Полный список с пояснениями — `deploy/mison-mcp.env.example`.

## Настройки

| Переменная | Описание |
|---|---|
| `MISON_API_KEY` | **Обязательна.** API-ключ заведения |
| `MISON_MCP_READONLY` | `true` — инструменты записи не подключаются совсем. Начните с этого |
| `MISON_MCP_GROUPS` | Какие группы подключить, через запятую: `core,reports,receipts,inventories,transfers,menu,orders,reservations,attendance`. По умолчанию все |
| `MISON_API_URL` | Адрес API, по умолчанию `https://backend.mison.uz/api/integrations/v1` |
| `MISON_MCP_MAX_CHARS` | Потолок размера одного ответа, по умолчанию 60000 знаков |

Описания всех инструментов занимают около 10 тысяч токенов контекста. Если ассистенту нужен
только анализ, оставьте `MISON_MCP_GROUPS=reports` — работать будет быстрее и точнее.

## Безопасность записи

- **Подтверждение человеком.** Каждый инструмент записи без `confirmed=true` ничего не
  отправляет: он возвращает итог («приход на 360 000, склад, поставщик»), который ассистент
  обязан показать человеку. Отправка — только повторным вызовом после явного «да».
- **Защита от дублей.** Приход, заказ, бронь и отметки уходят с `external_id` / `event_id`: если
  запрос повторился из-за обрыва сети, второго документа не будет.
- **Приход проводится сразу** и двигает остаток, себестоимость и долг поставщику; с `is_draft=true` ложится
  черновиком без проводок. Отмена — удалением документа в кабинете.
- **Инвентаризация по умолчанию — черновик:** остатки не двигаются, проводит человек в кабинете. Проведение
  сразу — только после расчёта и с токеном `check`: если пока шёл подсчёт остаток изменился, сервер ответит
  409 и ничего не спишет. Недостача при проведении попадает в прибыли и убытки. Отметки прихода-ухода влияют на зарплату по часам.
- **Перемещения.** Между своими складами проводятся сразу (остаток считает сервер, не хватает — 409). На другой логин
  по умолчанию создаётся черновик; отправка сразу (`is_draft=false`) списывает остаток, ставит долг получателю и
  уведомляет его — только по явной просьбе. Через API уходит товар, который списывается как есть, не по техкарте.
- **Чтение не меняет данные**, повторять его безопасно.
- **Куда уходят данные.** Ответы API читает ИИ-приложение, которое вы подключили, — они попадают его
  провайдеру (Anthropic, OpenAI и т. д.). Подключайте ключ только к тем ассистентам, которым
  доверяете данные заведения.

## Разработка

```bash
npm install
npm test        # мок-API и настоящий MCP-клиент по stdio
npm start       # нужен MISON_API_KEY
```

Структура: `src/client.js` — HTTP-клиент (токен, повторы при 401 / 429 / сбоях), `src/result.js` —
ответы и ошибки, `src/tools/*.js` — инструменты по группам. Новый отчёт API добавляется одним
`getTool({...})` в `src/tools/reports.js`; запись — через `writeTool`, она автоматически получает
`confirmed` и итог для подтверждения.
